# 连锁烘焙退场义务清算台

连锁面包店收缩门店时，把经营期、商品批次、中央工厂配送、现制损耗、订单履约、储值资金、
券核销、租赁设备、员工交接、供应商结算和承接方案按时间落成事件，并强制清算规则的服务。

## 目录

- `contracts/domain.schema.json`：对象、事件、聚合归属和载荷字段约定（27 个事件 / 6 个聚合）。
- `data/sample.json`：可直接校验的联调样例。
- `src/bakery_exit/`：
  - `contracts.py`：基础契约校验（不改写输入）。
  - `clock.py`：可控时钟，只能前进；恢复时对齐日志最后时间。
  - `store.py`：JSONL 仅追加事件存储，按聚合连续版本号，重启完整回放。
  - `canonical.py`：规范化序列化与快照哈希。
  - `projection.py`：从事件流重建台账、订单、余额、回执与暂停索引。
  - `service.py`：清算服务（冻结、三权分立、幂等、冲突暂停、权益互斥、独立确认）。
  - `scheduler.py`：按期限推进停产、取货退款、租约归还、结算阶段。
  - `views.py`：消费者 / 供应商 / 员工 / 总部角色视图与回执溯源。
  - `cli.py`：命令行事件契约校验。
- `tests/`：契约、清算规则、调度恢复、角色视图测试。
- `docs/domain.md`：领域对象、事件语义与上层服务规则。

## 核心规则

- **冻结快照**：停业决定发布即冻结债权债务（含快照哈希），冻结后不得新增债权债务。
- **损耗三权分立**：店长可报告并核实现场数量，但不能批准自己上报的损耗减免；审批须另有其人。
- **独立确认**：资金退款、寄售结算须资金清算方确认；订单与储值转承接门店须承接门店确认，
  储值转移需双方确认；资金确认人不能是本店店长。
- **回执幂等**：相同业务回执重放返回既有结果，不再转移资产或余额（闸门在所有业务校验之前，
  阶段已推进、权益已消耗后重放依然安全）。
- **冲突暂停**：编号相同但日期、范围或承接方不同 → `CLEARING_SUSPENDED`，裁决前不转移任何资产。
- **权益互斥**：退款、换店、提货竞争同一份订单权益时只有一种能成功；储值订单下单即在途划出，
  无法履行时恢复一次，不重复。
- **按来源恢复**：生效日前仍可履行的订单正常提货；生效日后无法履行的，储值退回余额、
  团购券/赠券恢复券权益。
- **核销去重**：券核销按编号全局去重，门店合并不重复计算；金额不一致直接拒绝。
- **阶段调度**：可控时钟到期自动跨越停产→取货退款→租约→结算，阶段只来自事件流，
  进程重启后延续原阶段、时钟不倒流、不重复推进。
- **角色可见性**：消费者只见本人订单与余额去向，供应商/员工只见各自交接事项；
  总部可从任一清算回执追到原门店、商品批次、责任人和未完成义务。
- **关闭门禁**：订单、余额、设备、员工、供应商、损耗、独立确认、暂停裁决全部完结才能关闭。

## 测试

```bash
python3 -m unittest discover -s tests
```

## 编译检查

```bash
python3 -m compileall -q src tests
```

## 样例校验

```bash
PYTHONPATH=src python3 -m bakery_exit.cli contracts/domain.schema.json data/sample.json
```

样例有效时输出 `valid`；发现问题时逐行给出字段、代码和中文说明，并返回非零状态。
